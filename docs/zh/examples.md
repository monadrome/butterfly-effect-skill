# 示例

## 编码工作流

观察到的纠偏：

- 先分析再修改。
- 必须在指定 worktree 工作。
- 保留 V2，通过开关新增 V3。
- 未明确要求时不要新增测试。

重开提示词：

> 先在指定 worktree 中只读分析现有行为、调用链和问题原因，未经确认不要修改。实现时保留 V2，通过默认关闭的开关新增 V3；配置读取留在入口，核心匹配逻辑使用纯函数和显式参数。默认只运行已有测试，不新增测试；提交和推送前检查 worktree 与 diff。

## 产品文案

观察到的纠偏：

- 从产品第一性原理出发，而不是套热门模板。
- 发布只是场景，不是前置条件。
- 高影响的发现描述需要先确认再修改。

重开提示词：

> 先确认产品的核心结果、用户动机、触发边界和行为不变量，不要从热门模板直接开始。把发布流程视为常见场景而非必要条件；先给出产品定位和 description 候选，等我逐项确认后再修改发现入口，并同步保持 Skill、README、package 和 marketplace 文案一致。

## 后来才发现的事实

如果会话后期才发现生产配置只改了一半，不应在重开提示词里把它写成已知事实，而应写成：

> 提方案前先拉取全部相关生产配置，区分未配置、空值和代码默认值，并沿路由、容器、过滤、PK 和最终输出追踪每个配置的实际影响。

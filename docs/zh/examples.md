# 示例

下面的案例展示编码、产品工作、调研和创意任务中的来源请求、观察到的纠偏、rewind 建议和更新后的提示词。示例文字只用于说明格式，实际结果必须以选定会话中的证据为准。

## 当前会话

调用：

```text
使用 $butterfly-effect 分析当前会话。
```

观察到的纠偏：

- 修改前先分析。
- 必须在指定 worktree 工作。
- 保留 V2，通过开关新增 V3。
- 未明确要求时不要新增测试。

Rewind 建议：

- 回退到：Agent 第一次选择实现路径之前。
- 原因：后续关于范围、兼容性和测试的纠偏都在修正这个最初假设。
- 保留：原始 V2 目标。
- 置信度：高。

更新后的提示词：

> 先在指定 worktree 中检查并解释现有行为、调用链和问题原因，不要修改代码。等我确认后再实现。保留 V2，通过默认关闭的开关新增 V3；配置读取留在入口，核心匹配逻辑使用纯函数和显式参数。运行已有测试，未明确要求时不要新增测试；提交和推送前检查 worktree 与 diff。

当前可见对话包含开局请求和有因果关系的 Agent 行动时，不需要读取本地会话。如果这些早期轮次已被截断，只在能够识别且可以访问时读取当前 session，不能搜索其他会话替代。

## 产品定位任务

一次产品定位会话中出现了这些纠偏：

- 从产品第一性原理出发，不要套用热门模板。
- 发布只是使用场景，不是前置条件。
- 修改高影响的发现文案前，先让用户确认。

Rewind 建议：

- 回退到：Agent 把热门发布模板当作产品定义之前。
- 原因：后续纠偏都在恢复产品的第一性原理和审批边界。
- 保留：发布是受支持的场景，以及已经接受的跨文件一致性要求。
- 置信度：高。

更新后的提示词：

> 先确认产品的核心结果、用户动机、触发边界和行为不变量，不要从热门模板直接开始。把发布流程视为常见场景而非必要条件；先给出产品定位和 discovery description 候选，等我明确选择后再修改，并同步保持 Skill、README、package 和 marketplace 文案一致。

## 调研或决策任务

一次工具选型会话中出现了这些纠偏：

- 不要在定义约束前直接选择热门方案。
- 区分有来源的证据、假设和未知信息。
- 比较运营成本、迁移风险和可逆性。
- 给出有适用条件的建议，不要宣布一个放之四海而皆准的赢家。

Rewind 建议：

- 回退到：Agent 未定义团队决策标准就选择热门方案之前。
- 原因：后续关于证据和取舍的要求都在修正这次缺少依据的比较。
- 保留：原始的工具选型目标。
- 置信度：高。

更新后的提示词：

> 先确认决策标准、受影响的用户、约束条件和时间范围，再比较候选方案。区分有来源的证据、假设和缺失信息；对时效性结论使用最新来源进行核验。比较运营成本、迁移风险和可逆性等取舍，然后给出带适用条件的建议，并附上一段简短的验证计划。

## 创意或设计任务

一次视觉识别会话中出现了这些纠偏：

- 打磨视觉稿前先确认受众和希望引发的反应。
- 先给出少量差异明确的方向，再选择其中一个。
- 保留既有的无障碍和品牌约束。
- 修改高影响的公开素材前先让用户确认。

Rewind 建议：

- 回退到：Agent 未先确认受众和约束就打磨单一视觉方向之前。
- 原因：后续纠偏补回了缺失的决策阶段、备选方向、无障碍检查和审批门槛。
- 保留：既有品牌约束和用户要求的公开载体。
- 置信度：高。

更新后的提示词：

> 先确认受众、希望引发的反应、既有品牌约束和无障碍要求。先给出两个或三个差异明确并说明取舍的方向，再制作最终素材。保持选定方向在所有目标载体中的一致性，检查对比度和内容是否适配；修改高影响的公开内容前先让用户确认。

## 指定本地会话

调用：

```text
使用 $butterfly-effect 分析 Codex 会话 "launch-plan"。
```

Skill 会定位这个本地会话，按时间顺序提取用户与 Agent 消息。除非工具载荷能够解释一次纠偏，否则不纳入分析。Claude Code 会话也可以用同样方式指定。遇到多个相似名称时，优先选择最强的精确匹配；只有这个假设会影响结果时，才需要说明。

## Transcript 或 Handoff

调用：

```text
使用 $butterfly-effect 分析 /work/exports/research-review.md。
```

直接路径会按原样读取，并保留消息顺序和说话人信息。分析调研笔记、文档评审、Issue 讨论或其他外部记录时，需要先导出内容或提供本地可读路径；Skill 不会自行抓取远端内容。

## Detailed 模式

调用：

```text
使用 $butterfly-effect --detailed 分析当前会话。
```

输出结构：

```markdown
## Rewind 建议

- 回退到：Agent 假定任务只是代码修改之前。
- 原因：后续纠偏改变了受众、证据和交付边界。
- 保留：原始目标和已经确认的约束。
- 置信度：中。

## 更新后的提示词

> 先检查……

## 已吸收的纠偏

- 分析门槛 -> 修改前先检查并解释。
- 兼容要求 -> 保留旧路径，通过开关接入新路径。

## 未纳入

- 具体根因是后来才查到的，因此改写成检查步骤。
- 一次性的语气反应证据太弱，不作为稳定偏好。
```

Rewind 建议和更新后的提示词始终放在最前面。Detailed 模式用于解释映射关系，不能用复盘报告替代这两个产物。

## 多条纠偏链

同一个会话中存在彼此独立的偏斜时，不要把无关目标强行放进同一个边界或同一段提示词。分别报告有依据的边界；如果合并会改变任务，就分别生成提示词。

示例：

- 链条 A：回退到 Agent 选择无依据的数据源之前；保留用户的目标受众和决策标准。
- 链条 B：回退到 Agent 未获确认就确定视觉方向之前；保留后续确认的无障碍要求。

除非一段更新后的提示词可以覆盖两条链而不混淆目标，否则应返回两条建议和两段可独立使用的提示词。

## 多个会话

调用：

```text
使用 $butterfly-effect 分析这三个会话导出文件，并为每个代表性案例生成独立的 Rewind 建议和更新后的提示词。
```

先分别分析每个来源，再进行比较。每段提示词都要有清楚的标题，并且能够独立使用。只有重复出现或用户明确要求保留的规则，才能成为跨会话指导；无关的一次性决定仍留在原案例中。

## 后来才发现的事实

假设会话后期才发现问卷只覆盖了活跃客户，不要把它写成开局时已知的事实：

```text
问卷只覆盖了活跃客户。
```

应改成调查要求：

> 下结论前，先检查问卷的抽样标准、招募渠道、时间范围和缺失群体；区分现有证据能够支持的结论，以及需要扩大样本或补充其他来源才能判断的部分。

## 稳定偏好与一次性决定

证据：

- 用户在多个会话中都要求“行动前先分析”，并明确要求 Agent 记住。
- 某一次会话因为评审人暂时无法参与，用户临时要求不要做利益相关者评审。

处理方式：

- 在适用的任务里，把分析门槛作为稳定协作偏好。
- 临时评审限制只进入那次任务的重开提示词，不能概括成“用户从来不想评审”。

## 历史缺失与隐私

如果指定会话无法读取，用一句话说明来源缺失，再仅依据当前仍可见的证据生成结果。不要编造丢失的纠偏或精确的回退位置。

如果没有证据支持任何实质纠偏链，则返回 `No reliable drift or rewind point detected`，并以原始目标为基础生成更新后的提示词。

如果 transcript 中含有 token、客户标识符或无关的个人信息，输出时应删除。相关操作要求确实重要时，可以改写成“使用已配置的服务账号完成认证”，但不能复述具体值或身份。

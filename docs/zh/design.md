# 设计说明

蝴蝶效应是一个事后的轨迹偏斜诊断工具。它分析已经发生的 AI 协作会话，先判断已经形成的任务产出物是否因不符合预期而被返工，存在偏斜时再定位最早有依据的边界，并返回 rewind 建议和更新后的提示词，用于从该节点继续同一个任务。任务可以是编码、调研、写作、设计、规划、运营或其他工作。

## 产品定位

| 原则 | 含义 |
|---|---|
| 零准备 | 直接使用已经存在的会话记录，不要求事先安装追踪器、hook 或标记每次纠偏。 |
| 产出物优先诊断 | 解释后续请求之前，先确认已经形成的任务产出物因不符合预期而被返工。 |
| Rewind-first | 先返回有证据支持的最早偏斜边界及其与产出物返工的关系，再返回从该节点继续所需的提示词；分析依据只在 `--detailed` 模式下作为辅助信息出现。 |
| 反事实分支 | 从选定的历史节点构造更好的后续轨迹，同时尊重该节点真正可知的信息范围。 |
| 领域中立 | 保留任务自身的受众、产物、证据标准和验收条件，不把编码场景的默认规则带入其他领域。 |

零准备不等于没有输入。Skill 仍然需要当前可见的会话、能够定位的会话名称，或用户提供的 transcript 路径。已经丢失的历史无法凭空还原。

领域术语和决策理由记录在 [CONTEXT.md](../../CONTEXT.md) 与 [ADR 0001](../adr/0001-artifact-first-drift-diagnosis.md) 中。

## 证据模型

首要证据是任务产出物及其版本，而不是给每条用户消息贴上的主观标签。

| 证据 | 处理方式 |
|---|---|
| 已形成的产出物版本因不符合预期而被返工 | 证明发生偏斜，并支持因果分析 |
| 产出物版本形成前追加要求 | 更新当前目标，不证明偏斜 |
| 已接受的产出物随后正常扩展功能或范围 | 正常继续，不证明偏斜 |
| 重复解释、状态说明或上下文管理消息 | 没有任务产出物返工，返回无可靠结果 |
| 确认偏斜后的相关要求 | 定义正确产出物时，作为后续约束纳入 |
| 重复出现的偏好，或明确要求记住的规则 | 与当前任务相关时，作为稳定偏好纳入 |
| 调查后才发现的事实 | 改写成检查、复现或验证指令 |
| 偶然的领域细节或缺乏依据的性格推断 | 删除，或概括成背后的真实意图 |

项目规则和已经接受的最终决定也可以支撑提示词条款。后续要求可以描述正确产出物，但不一定证明偏斜已经发生。删除孤立反应和推断出的性格特征。能读取原始消息时，自动生成的摘要只能作为次级证据。

## 轨迹偏斜与 Rewind 模型

诊断单位是任务产出物及其已经形成的版本。任务产出物是可以脱离 Agent 上下文管理独立评价的用户目标成果，例如代码、文档、设计、计划或最终分析。未完成的回答、状态更新和普通对话不是产出物，除非该回答本身就是用户要求交付的成果。

只有已经形成的产出物版本因不符合预期结果或适用约束而被返工时，才发生偏斜。rewind 点是替换后本可以避免该返工的最早 Agent 假设或行动。只有因果行动清晰可见时，才使用精确轮次或时间戳；证据只能支持某个因果阶段时，使用描述性边界，不编造标识。多处独立的产出物偏斜否定了共同 rewind 点，但可以各自保留有依据的边界。没有返工过的产出物或因果边界时，返回 `No reliable drift or rewind point detected`。

更新后的提示词要保留仍然有效的早期决定，并把后见信息改写成检查要求。它必须能够避免对应的产出物返工，但不能把后来才发现的根因直接断言成开局事实。返回无可靠结果时不附带更新后的提示词，除非用户明确要求基于有限证据重建。

## 重建顺序

1. 识别用户目标产出物及其已经形成的版本；没有版本因不符合预期而返工时，返回无可靠结果。
2. 把每次有依据的产出物返工追溯到替换后本可以避免返工的最早 Agent 行动。
3. 把相关后续要求作为继续执行的约束纳入，并将后见事实保留为检查或验证任务。
4. 检查每条保留的后续约束和提示词条款，再返回结果。

最终提示词必须可以脱离复盘独立使用。从选定节点继续的 Agent 不应依赖后续对话，也能理解目标、决策门槛、执行约束和验收要求。

## 后见信息边界

用户在任务开始时本来就可以说明的要求，可以直接进入提示词。任务过程中才发现的原因、隐藏依赖、来源局限或环境约束不可以。

后来发现：

```text
来源数据只覆盖了一个地区。
```

从历史节点继续的条款：

```text
下结论前，先验证来源覆盖范围和地区范围。
```

这样既保留了返工带来的经验，也没有伪造先验知识，更不会在验证前过早指定具体解法。

## 矛盾与证据

同一阶段、同一范围内发生冲突时，以较晚的明确决定为准。较早的指令仍可能在其他阶段成立。例如，“暂时不要定稿”在用户后来批准发布后，可以保留为审查门槛，而不是永久禁止发布。

优先采用明确说出、重复出现、被最终结果接受，或有项目规则支持的要求与偏好。删除一次性的情绪反应和推断出的性格偏好，除非其他来源支持同一规则。根据可见因果证据选择精确边界、描述性边界或无可靠结果。

## 非目标

- 蝴蝶效应不是会话记录器。它在有价值的历史已经存在后工作。
- 它不是持久记忆。跨会话偏好需要重复证据，或用户明确要求记住。
- 它不是通用提示词优化器。每个新增条款都必须来自产出物证据、后续约束或权威项目上下文。
- 它不是以报告为主的复盘工具。确认存在偏斜后，默认交付物是简洁的 rewind 建议和更新后的提示词。
- 它不会让后续轨迹获得全知视角。未知事实仍然需要调查。

## 反事实验证

返回提示词前，逐项检查：

1. 历史中是否存在因不符合预期而被返工的任务产出物版本？
2. 替换建议的因果行动是否本可以避免这次返工？
3. 每条纳入的要求在选定节点是否适用；后见信息是否已经改写成调查任务？
4. 提示词是否保留了原始目标，而不是为了回避不确定性缩小任务？
5. 重复约束能否合并，同时不丢失行为要求？

## 常见失败方式

| 失败方式 | 后果 | 防护方式 |
|---|---|---|
| 用 transcript 摘要代替原始消息 | 产出物版本、返工证据的顺序或归属可能丢失 | 优先读取按时间排列的用户与 Agent 消息 |
| 识别产出物之前先给消息分类 | 版本形成前的要求和普通后续请求制造虚假偏斜 | 先识别已经形成的产出物版本及其返工 |
| 把重复解释当作偏斜 | 会话轮次制造虚构 rewind 点 | 必须存在用户目标产出物的返工 |
| 把已接受产出物的正常演进当作偏斜 | 新范围被误写成早期失败 | 必须有证据表明旧版本不符合预期 |
| 没有产出物偏斜也生成提示词 | 固定格式压力制造虚构诊断和无依据规则 | 返回无可靠结果 |
| 把一次反应当成稳定偏好 | 提示词过度拟合用户 | 要求重复证据、明确记忆意图或最终接受 |
| 把后来查到的根因写成已知事实 | 更新后的提示词泄漏后见信息 | 改写成检查或验证步骤 |
| 把第一条后续要求当作 rewind 点 | 建议回退得太晚，原始偏斜仍然存在 | 沿产出物返工向前追溯到更早的 Agent 假设或行动 |
| 先输出长篇分析 | 用户还要自己把报告翻译成指令 | 先放简洁的 rewind 建议和更新后的提示词 |

## 评估方式

仓库检查能够验证静态契约、引用、插件清单、语言边界、发布 tag 和包内容，但不能证明模型识别产出物返工及其因果边界的准确率。

行为评估应在新鲜上下文中使用未经加工的 transcript，并覆盖代码或文档被返工、处理中追加格式要求、多次解释代码、已接受产出物的正常演进、多处独立偏斜、历史缺失和弱因果等场景。不要提前提供期望提示词或目标分类。检查结果是否先识别产出物偏斜、对非偏斜场景返回 no-op、只定位有依据的边界、纳入相关后续约束、排除无依据的推断、保留原始目标，并把后来发现的事实转换成检查要求。

# 设计说明

## 为什么提示词优先

用户调用蝴蝶效应，是为了重新开始得更好。如果默认输出一篇长复盘，用户仍然需要自己把分析翻译成指令，等于重复完成 Skill 应承担的工作。因此默认只输出最终提示词。

## 避免事后知识泄漏

纠偏可能暴露两类信息：一类是用户原本就可以提前说明的要求，另一类是必须调查后才能知道的事实。前者直接进入重开提示词，后者必须转换成“先检查、验证或比较”的指令。

## 避免过拟合

提示词应防止同类纠偏，而不是保留所有实现痕迹。“不要从对象字段读取开关”可以抽象成“核心逻辑使用显式输入”；一次性的变量名通常不应进入提示词。

## 反事实验证

最终检查的核心问题是：一个新 Agent 只看到这段启动提示词，能否避免所有高置信度纠偏，同时不需要拥有最初不可能知道的信息。
